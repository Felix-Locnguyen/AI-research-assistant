# EPIC 09 — Background Queue & Rate Limiting (T58–T60)

## Goal

Webhook trả về ngay lập tức; tin nhắn được xử lý nền qua hàng đợi với retry/dead-letter; giới hạn tần suất gọi LLM và API ngoài. Deliverable: *"System stays stable under many concurrent messages."*

## Key decisions (đã chốt với user)

- **Queue xử lý TẤT CẢ tin nhắn đến:** webhook xác thực chữ ký → `enqueue(IncomingMessage)` → trả 200 ngay; worker chạy `handle_message` + gửi reply. Không còn xử lý inline trong webhook.
- **In-memory only:** `asyncio.Queue` thuần, retry/dead-letter giữ trong RAM — mất khi restart (trade-off có chủ đích; webhook đã trả 200 nên platform không redeliver; queue đầy → **503** để platform redeliver thay vì mất im lặng).
- **Single worker (FIFO 1 task):** giữ thứ tự hội thoại per-user (2 worker sẽ đan xen read-modify-write lịch sử cùng user). Research dài sẽ chặn job sau — chấp nhận được ở quy mô personal assistant; ghi chú trong docstring để sau này biết cần per-user lock nếu tăng worker.
- **Không bao giờ chạy lại `handle_message` sau khi nó đã thành công** (tránh lặp lượt hội thoại): handle lỗi → retry cả job; handle OK + send lỗi → chỉ retry phần gửi.
- **429 (quota Gemini) → dead-letter NGAY, không retry** — đồng nhất triết lý `llm.py:16`.
- **Không thêm dependency** (no celery/redis/aiolimiter); knobs là hằng module (không đưa vào config.py) — theo style `llm.py`/`research.py`.
- **Import style:** `from app.core.queue import QueueFullError, enqueue` trong các kênh → test monkeypatch `app.channels.telegram.enqueue` (bound name trong module under test). `main.py` dùng `from app.core import queue` cho `queue.worker()`.

### 1. NEW `app/core/ratelimit.py` (T60)

```python
"""Giới hạn tần suất gọi LLM và API ngoài (T60) — không dùng thư viện ngoài."""
# constants: LLM_MAX_CONCURRENT=1, LLM_MIN_INTERVAL_SECONDS=0.2,
#            SEARCH_MAX_CONCURRENT=1, SEARCH_MIN_INTERVAL_SECONDS=1.0

class RateGate:
    """Semaphore + khoảng nghỉ tối thiểu giữa các lần acquire.
    Đo khoảng nghỉ dưới lock rồi sleep NGOÀI lock (tránh stampede)."""
    def __init__(self, max_concurrent: int, min_interval: float) -> None:
        self._sem = asyncio.Semaphore(max_concurrent)
        self._min_interval = min_interval
        self._lock = asyncio.Lock()
        self._next_allowed = 0.0  # time.monotonic()

    @asynccontextmanager
    async def acquire(self) -> AsyncIterator[None]:
        await self._sem.acquire()
        try:
            async with self._lock:
                now = time.monotonic()
                wait = max(0.0, self._next_allowed - now)
                self._next_allowed = max(now, self._next_allowed) + self._min_interval
            if wait > 0:
                await asyncio.sleep(wait)
            yield
        finally:
            self._sem.release()

LLM_GATE = RateGate(LLM_MAX_CONCURRENT, LLM_MIN_INTERVAL_SECONDS)
SEARCH_GATE = RateGate(SEARCH_MAX_CONCURRENT, SEARCH_MIN_INTERVAL_SECONDS)
```

### 2. FILL `app/core/queue.py` (T58+T59) — currently empty

Hằng: `QUEUE_MAXSIZE=1000`, `MAX_ATTEMPTS=3`, `RETRY_BACKOFF_SECONDS=1` (1s, 2s, 4s), `DEAD_LETTER_LIMIT=50`.

Cấu trúc:
- `class QueueFullError(Exception)` — webhook chuyển thành HTTP 503.
- `@dataclass(frozen=True) DeadLetter`: `channel, user_id, text_snippet, phase ("handle"|"send"), attempts, error, failed_at` (naive-UTC `datetime.now(UTC).replace(tzinfo=None)`).
- Module-level: `_queue: asyncio.Queue[IncomingMessage] = asyncio.Queue(maxsize=QUEUE_MAXSIZE)`, `_dead_letters: deque[DeadLetter] = deque(maxlen=DEAD_LETTER_LIMIT)`.
- `def enqueue(message) -> None` — `put_nowait`; `asyncio.QueueFull` → log warning tiếng Việt → `raise QueueFullError(...) from None`.
- `def _is_rate_limited(exc) -> bool` — `getattr(exc, "code", None) == 429`.
- `async def _retry(phase, message, op)` — tối đa `MAX_ATTEMPTS`; `CancelledError` → re-raise; 429 → log error + dừng ngay; khác → log warning + `await asyncio.sleep(RETRY_BACKOFF_SECONDS * 2**(attempt-1))`; hết → ném exception cuối.
- `async def _handle_phase(message) -> str` — `async with SessionLocal() as session: return await handle_message(message, session)` bọc trong `_retry("handle", ...)`.
- `async def _send_phase(message, reply)` — `await send_text(message.channel, message.user_id, reply)` (dispatcher từ `base`; messenger → `proactive=False` → RESPONSE) bọc trong `_retry("send", ...)`.
- `def _dead_letter(message, phase, attempts, exc)` — append vào deque + `logger.error("DEAD-LETTER phase=%s kênh=%s user=%s attempts=%s text=%r error=%s", ...)`.
- `async def _process_job(message)` — log info; try handle → except → dead-letter phase="handle" + return; try send → except → dead-letter phase="send" (KHÔNG chạy lại handle). `CancelledError` luôn re-raise.
- `async def worker()` — loop vĩnh viễn: `message = await _queue.get()` → try `_process_job` (lưới an toàn `logger.exception`) → `finally: _queue.task_done()`. Cancel khi lifespan shutdown.
- `def _reset_for_tests(maxsize=QUEUE_MAXSIZE)` — `global _queue`; rebind queue mới + `_dead_letters.clear()`. (enqueue lookup `_queue` qua module globals lúc gọi — hoạt động đúng.)

Docstring ghi: in-memory only; single worker FIFO + lý do (per-user order); handle thành công không bao giờ chạy lại.

Import: `from app.channels.base import IncomingMessage, send_text`, `from app.conversation.handler import handle_message`, `from app.database.connection import SessionLocal`. **Không cycle:** channels → core.queue → handler/base; handler/base không import queue.

## Edge cases

| Tình huống | Xử lý |
|---|---|
| Queue đầy (1000 job) | `QueueFullError` → webhook **503** (platform redeliver); poll → log + drop |
| 429 quota Gemini | Dead-letter NGAY, 1 attempt (không retry — `llm.py:16`) |
| handle lỗi tạm thời (500/mạng) | Retry ≤3, sleep 1s/2s trong worker |
| handle OK, send lỗi | Chỉ retry send — KHÔNG chạy lại handle (tránh lặp history/extractor) |
| send hết retry | Dead-letter phase="send" (history đã có reply, user chưa nhận — chấp nhận, in-memory) |
| Worker bị cancel khi shutdown | `CancelledError` re-raise; `task_done()` vẫn chạy (finally); không dead-letter job bị cancel |
| Payload messenger nhiều tin, đầy giữa chừng | Job đầu đã vào, 503 cho phần còn lại → redelivery có thể trùng lặp — hiếm, ghi chú בלבד |
| Non-text/echo/bad signature/bad JSON | Như cũ — không đến enqueue |
| Notifier/scheduler | Vẫn gửi trực tiếp qua `base.send_text` — KHÔNG qua queue (đã chốt) |
| Multi-process uvicorn | Mỗi process có queue riêng — docker-compose chạy 1 process, chấp nhận được |
| Gate giữ qua backoff sleep | BỊ CẤM — gate chỉ quanh call API (comment trong llm.py) |
| `/health` | Không đổi (queue stats = EPIC 11) |
