# EPIC 07 — Reminder System (T48–T53)

## Goal

Người dùng đặt lời nhắc bằng ngôn ngữ tự nhiên qua chat và nhận thông báo đúng giờ trên kênh của mình. Đầy đủ T48–T53: CRUD + phân tích thời gian tiếng Việt (LLM qua tool) + scheduler + notifier + lặp lại ngày/tuần + múi giờ per-user (mặc định `Asia/Ho_Chi_Minh`, lưu ở `user_preferences['timezone']`).

## Key decisions (đã chốt)

- T49: Gemini đọc thời gian tiếng Việt rồi truyền `remind_at` (ISO 8601) vào tool — không thêm thư viện dateparser.
- T53: `remind_at` lưu naive-UTC (`datetime.now(UTC).replace(tzinfo=None)` như hiện có); ISO naive → hiểu theo tz của user → UTC; ISO có offset → convert về UTC; hiển thị theo tz user (stdlib `zoneinfo`).
- T50: scheduler = background loop trong lifespan (giống `_cleanup_loop` ở `app/main.py`), tick 60s — không APScheduler/celery.
- T51: notifier dispatch theo `User.channel`; `telegram` → `telegram.send_text`; kênh khác log warning (EPIC 08 làm sau).
- Schema: thêm cột `repeat` (`none|daily|weekly`) vào `reminders`. `create_all` không ALTER bảng cũ → migration idempotent trong `init_db()`: `ALTER TABLE reminders ADD COLUMN IF NOT EXISTS repeat VARCHAR(16) NOT NULL DEFAULT 'none'`. Không cần cột khác (`is_done` + `remind_at` đã đủ trạng thái).

## Files (theo thứ tự thực hiện)

1. `app/database/models.py` — thêm `repeat` vào `Reminder`
2. `app/database/connection.py` — ALTER idempotent trong `init_db()`
3. `app/database/repository.py` — `ReminderRepository`: `add/get/update/delete/list_for_user/list_due(now, limit=50)` (`remind_at <= now AND NOT is_done`)
4. `app/reminders/service.py` (fill) — `_user_tz`, `parse_remind_at(raw, tz)`, `create_reminder`, `list_reminders`, `update_reminder`, `delete_reminder`, `format_reminder`, `next_occurrence`, `mark_fired`
5. `app/reminders/notifier.py` (fill) — `notify(session, user_id, reminder) -> bool`: soạn tin `🔔 Nhắc nhở: {text}\nThời gian: {HH:MM DD/MM/YYYY} (giờ {tz})` (+ dòng lặp lại nếu có), gửi qua channel; lỗi gửi → swallow-and-log như `telegram.py`, trả False
6. `app/reminders/scheduler.py` (fill) — `run_once()` (SessionLocal riêng mỗi tick) + `run_loop()` (sleep 60 + try/except log)
7. `app/conversation/tools.py` — một `REMINDER = types.Tool` với 4 declaration: `create_reminder(text, remind_at, repeat?)`, `list_reminders()`, `update_reminder(reminder_id, text?, remind_at?, repeat?)`, `delete_reminder(reminder_id)`; `execute()` thêm 4 nhánh gọi service, bắt `ValueError` → trả thông điệp tiếng Việt làm tool result; id trả về dạng `id=N` như memory tools
8. `app/conversation/handler.py` — thêm `tools.REMINDER` vào list tools
9. `app/main.py` — spawn `scheduler.run_loop()` trong lifespan, cancel ở `finally`
10. `prompts/assistant.md` — rule: đặt/nhắc lịch → `create_reminder` với `remind_at` ISO (giờ local user); sửa/xóa → gọi `list_reminders` trước để lấy id

## Chi tiết đáng nhớ

- Service từ chối `remind_at` ở quá khứ / ISO hỏng bằng `ValueError` tiếng Việt ("Thời gian nhắc phải ở tương lai...", "Không hiểu định dạng thời gian...") — không tự sửa ngầm.
- Lặp lại (`mark_fired`): `none` → `is_done = True`; `daily|weekly` → cộng 1|7 ngày, `while remind_at <= now: += delta` (bỏ qua các lần đã lỡ khi server down, chỉ giữ lần tương lai kế tiếp).
- Gửi thất bại → không đánh dấu done, tick sau thử lại (mất lời nhắc tệ hơn retry mỗi phút).
- Reminder ID lệch scope theo `user_id` trong mọi truy vấn (như MemoryRepository).

## Verification (không cần LLM trước, LLM sau)

1. Boot app → cột `repeat` xuất hiện (kiểm tra qua SQL); boot lần 2 không lỗi (idempotent)
2. CRUD `ReminderRepository` với row `remind_at = now - 1min` → `list_due` trả về; filter `is_done` đúng
3. Unit `parse_remind_at`: naive `"2025-12-01T08:00:00"` + tz VN → UTC `01:00`; aware `+07:00` → UTC; quá khứ/garbage → ValueError tiếng Việt
4. `next_occurrence`: daily/weekly tiến tới tương lai; `remind_at` lùi 3 ngày (server down) → nhảy tới lần tương lai kế; `none` → None
5. Scheduler: seed reminder đã đến hạn cho user telegram thật (hoặc mock `send_text`) → `run_once()` → nhận tin, row done/được lặp lại đúng
6. Notifier âm: user `channel="zalo"` → log warning, không crash, không mark done
7. (Khi quota Gemini reset) e2e `handle_message`: "nhắc tôi họp lúc 8h sáng mai" → row đúng UTC; LLM 429 vẫn chịu được (fallback đã có)
